⚠️ Pendências de segurança
Newsletter AJAX sem nonce CSRF risk
O handler tecnoinfor_subscribe_newsletter() em theme-helpers.php processa $_POST['email'] sem check_ajax_referer(). Qualquer site pode enviar um POST para admin-ajax.php?action=subscribe_newsletter e disparar e-mails ao administrador.

REST endpoint LGPD sem rate limiting e com __return_true abuso possível
permission_callback => '__return_true' em api-lgpd.php deixa o endpoint aberto a qualquer chamada sem autenticação. Sem rate limiting, um script pode spam-chamar o endpoint e forçar a definição de cookies arbitrários. Considerar limitar por IP via transient ou adicionar um nonce REST.

// Adicionar nonce na chamada REST do main.js: headers: { 'X-WP-Nonce': wpApiSettings.nonce } // No endpoint: 'permission_callback' => function() { return wp_verify_nonce( $_SERVER['HTTP_X_WP_NONCE'] ?? '', 'wp_rest' ); },
15 ocorrências de _e() em vez de esc_html_e() no index.php PHPCS warning
_e() não escapa o output — se uma tradução no banco de dados for comprometida (ex: via painel de tradução do próprio tema), pode conter HTML arbitrário. O padrão do WP agent-skills (e PHPCS WordPress ruleset) exige esc_html_e() para texto puro. O CI com PHPCS irá falhar nestes pontos.
index.php, linhas 63, 157, 170, 183, 246, 248, 309, 334, 339, 387, 403, 509, 525, 529, 581
<?php _e('Satisfied Clients', 'tecnoinfor'); ?> <?php esc_html_e('Satisfied Clients', 'tecnoinfor'); ?>
